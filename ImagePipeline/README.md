#  ImagePipeline

## 소개
- 앱의 스크롤 화면에서 이미지가 빠르고 정확하게 노출되도록 구현

## 구현 범위
- URL 기반 비동기 이미지 로딩
- 중복 요청 병합
- 요청 취소
- 메모리 캐시
- Cell reuse 대응
- MainActor에서 UI 반영
- 이미지 다운샘플링
- 실패 시 재시도 여부 판단

## 시나리오
1. 같은 이미지 URL을 여러 셀이 동시에 요청한다.
2. 셀이 재사용되어 요청이 취소된다.
3. 한 소비자만 취소하고 다른 소비자는 이미지를 계속 기다린다.
4. 네트워크 응답은 왔지만 셀은 이미 다른 데이터를 표시하고 있다.
5. 큰 이미지를 원본 크기로 디코딩해 메모리가 급증한다.
6. 캐시에 이미지가 있지만 요청한 표시 크기와 맞지 않는다.
7. 이미지 디코딩이 메인 스레드에서 수행되어 스크롤이 끊긴다.

## ImagePipeline 구성
- 이미지 요청을 위한 네트워크
- 요청한 이미지를 메모리 상에서 관리하기 위한 캐시
- 이미지를 만들기 위한 디코더
